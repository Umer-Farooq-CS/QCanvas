# Benchmark: Curated vs. Expanded Knowledge Base

This document outlines the benchmarking methodology and results comparing the performance of the Cirq RAG Code Assistant when using a small, high-precision curated knowledge base versus a larger, automatically extracted expanded knowledge base. 

This test was performed to directly address the critique that a 140-entry knowledge base is too small for a robust code generation system.

## 1. Methodology

The benchmark evaluates the end-to-end performance of the orchestrator pipeline (`Designer` \u2192 `Validator` \u2192 `Optimizer` \u2192 `Final Validator`) on a local `qwen2.5-coder:7b-instruct-q4_K_M` model. 

### Datasets Tested
1. **Phase 1 (Curated KB):** 140 entries. High-quality, manually verified Cirq code snippets spanning 12 topic areas. (Default configuration).
2. **Phase 2 (Expanded KB):** 700 entries. Generated by extracting and filtering snippets from the official Cirq documentation and an annotated dataset using `scripts/expand_knowledge_base.py`.

### The Benchmark Dataset
The system was evaluated against 25 standardized prompts located in `data/datasets/benchmark_prompts_v2.jsonl`. These prompts are evenly divided into 5 tiers of complexity:
- **Basic:** Simple circuit construction (e.g., Bell state, GHZ state).
- **Intermediate:** Algorithms requiring control flow or specific features (e.g., QFT, Teleportation).
- **Algorithm:** Full algorithm implementation (e.g., VQE, QAOA).
- **Advanced:** Complex hardware/API features (e.g., noise models, custom gates).
- **Explanation:** Conceptual explanations accompanied by code.

### Scoring Metrics
Each generated solution is scored using:
- **Syntax Validity (30%):** Does the code parse as valid Python?
- **Compilation Success (30%):** Does the code compile without execution errors or missing dependencies?
- **Circuit Validity (20%):** Is a non-empty `cirq.Circuit` created?
- **Measurement Inclusion (20%):** Are measurements present in the circuit (if applicable)?

An overall "Pass" is awarded only if the code executes flawlessly and passes the internal Semantic Validator.

## 2. Benchmark Results

**Date Run:** June 16, 2026
**LLM Used:** `qwen2.5-coder:7b-instruct-q4_K_M` (Local Ollama)

### High-Level Metrics Comparison

| Metric | Phase 1 (Curated KB: 140) | Phase 2 (Expanded KB: 700) | Delta |
|--------|---------------------------|----------------------------|-------|
| **Overall Pass Rate** | **64.0%** (16/25) | 52.0% (13/25) | -12.0 pp |
| **Avg Quality Score** | **0.820** | 0.748 | -0.072 |
| **Avg Latency** | **45.31 s** | 48.43 s | +3.12 s |

### Performance by Prompt Tier

| Tier | Curated Pass Rate | Expanded Pass Rate | Delta |
|------|-------------------|--------------------|-------|
| **Basic** | 80.0% (4/5) | **100.0%** (5/5) | +20.0 pp |
| **Intermediate** | **40.0%** (2/5) | 20.0% (1/5) | -20.0 pp |
| **Algorithm** | **40.0%** (2/5) | 20.0% (1/5) | -20.0 pp |
| **Advanced** | **60.0%** (3/5) | 40.0% (2/5) | -20.0 pp |
| **Explanation** | **100.0%** (5/5) | 80.0% (4/5) | -20.0 pp |

### Conclusion
Empirical testing demonstrates that expanding the knowledge base using automated extraction actually **decreases the overall system reliability by 12 percentage points**. The larger RAG context introduces "noisy" or sub-optimal code snippets that confuse the 7B parameter LLM.

**Decision:** The system will retain the 140-entry Curated Knowledge Base as its default configuration, prioritizing retrieval precision over total volume.

## 3. Reproducibility

To reproduce these benchmark results on your local machine:

1. **Ensure Ollama is running** with the `qwen2.5-coder` model pulled.
2. **Expand the Knowledge Base** (Creates a temporary 700-entry KB):
   ```bash
   conda run -n cnn python scripts/expand_knowledge_base.py
   ```
3. **Run the Benchmark Script**:
   ```bash
   conda run -n cnn python scripts/run_local_benchmark.py --prompts 25
   ```
   *Note: This script will automatically backup the active KB, run the curated benchmark, run the expanded benchmark, and then restore the curated KB when finished.*
4. **View the Output:** Detailed JSON reports are saved to `outputs/reports/benchmark_comparison_<timestamp>.json`.
